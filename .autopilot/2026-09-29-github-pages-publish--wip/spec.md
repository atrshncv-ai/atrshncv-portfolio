# Спецификация

## 1. Цель

Опубликовать имеющееся русскоязычное портфолио из репозитория `atrshncv-design/atrshncv-portfolio` на бесплатном GitHub Pages. Сохранить разделы, кейсы, визуальный стиль, изображения и адаптивную вёрстку текущего сайта. Репозиторий публичный, поэтому сайт будет общедоступен.

## 2. Требования

| ID | Результат |
|---|---|
| R01 | Использовать код и материалы указанного репозитория как исходник. |
| R02 | Сохранить существующую страницу-портфолио и сделать её доступной как сайт. |
| R03 | Публиковать сайт на GitHub Pages из этого репозитория. |
| R04 | Не требовать платного тарифа, домена или внешнего сервера для основной страницы. Использовать бесплатный адрес GitHub Pages. |
| G01 | Сохранить бесплатный Pages-вариант; AI-чат и форма контактов должны направлять посетителя в Telegram или почтовое приложение. Не показывать, будто сообщение отправлено автоматически. |
| R05i | Сохранить материалы портфолио и текущую визуальную основу. |

## 4. Решения реализации: публикация

- Next.js собирает приложение в статические файлы в `out/`.
- Поскольку URL репозитория использует путь `/atrshncv-portfolio/`, приложение и локальные файлы должны корректно работать под этим префиксом.
- GitHub Actions запускает установку по `package-lock.json`, собирает сайт и передаёт только содержимое `out/` в GitHub Pages.
- Workflow запускается при отправке изменений в `main`; сборка также доступна вручную через Actions.
- В настройках репозитория источник Pages должен быть `GitHub Actions`.
- Используется бесплатный адрес `https://atrshncv-design.github.io/atrshncv-portfolio/`; покупка и настройка домена не входят в работу.
- Репозиторий сейчас публичный; это проверено на указанной странице GitHub, поэтому для него подходит бесплатный тариф Pages.

Статический экспорт Next.js создаёт файлы в `out/` и рассчитан на хостинг, который раздаёт HTML, CSS и JavaScript. Динамические API-обработчики и серверная обработка форм в этом режиме не поддерживаются. Основание: [Next.js Static Exports](https://nextjs.org/docs/app/guides/static-exports).

## 5. Решения реализации: связь с автором

- Существующие контакты Telegram и email остаются доступны на странице.
- AI-чат заменяется компактной статической панелью связи с выбором Telegram или email; она не делает запросов к `/api/chat` и не имитирует ответ LLM.
- Форма контактов сохраняет ввод имени, email, компании, типа запроса и сообщения. При отправке браузер открывает черновик письма на существующий адрес из репозитория с заполненной темой и текстом; посетителю явно сообщается, что письмо отправляется его почтовым приложением.
- Посетитель может также написать через прямую Telegram-ссылку. Никакие поля не отправляются на сервер сайта.
- Серверные маршруты, нужные только для прежнего чата и формы, не входят в публикуемую статическую версию.

## 6. Решения реализации: сохранение сайта

Существующие секции «Главная», «Обо мне», «Процесс», «Навыки», «Проекты», «Опыт», «Контакты» и «Подвал», кейсы, контакты и изображения сохраняются. Визуальное оформление и тексты меняются только там, где это нужно для ясного статического поведения чата и формы. SEO-адрес сайта указывает на фактический бесплатный Pages URL.

## 7. Проверяемые критерии приёмки

1. Команда сборки создаёт `out/index.html` и не требует запущенного Node-сервера для показа сайта.
2. GitHub Actions workflow собирает `out/` и публикует его через GitHub Pages.
3. В экспортированной странице ссылки на скрипты, стили и публичные изображения разрешаются под `/atrshncv-portfolio/`.
4. Разделы, тексты, изображения и адаптивное оформление портфолио остаются в опубликованном сайте.
5. Форма открывает черновик письма с заполненными данными; сайт не отправляет POST-запрос.
6. Панель чата предлагает действующие Telegram/email-ссылки и не делает запрос к серверному API.
7. Публикация не требует API-ключей или платных сервисов.

## 8. Границы и швы

Ярус T1: одна функция — публикация существующего портфолио, — проходящая через приложение и GitHub Pages workflow. Границы разделяют статический экспорт и публикацию; второй модуль потребляет выход первого.

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| Статическое приложение Next.js | Страницей портфолио, поведением панели связи и формы, локальными ресурсами | `npm run build` создаёт сайт в `out/`, пути ресурсов работают под `/atrshncv-portfolio/` | Компоненты интерфейса и детали сборки; серверные API прежней версии не публикуются |
| Публикация GitHub Pages | Сборкой и передачей каталога `out/` в Pages при push в `main` или ручном запуске | Публичный Pages-сайт по бесплатному адресу репозитория | Внутренние шаги GitHub Actions и состояние статического приложения |

**Швы приёмки:** (1) production-сборка приложения создаёт `out/`, а экспортированные HTML, скрипты, стили и изображения разрешаются с базовым путём `/atrshncv-portfolio/`; (2) Pages workflow устанавливает зависимости из lock-файла, запускает эту сборку и публикует её каталог `out/`. Автоматизированные тесты не добавляются; проверяется production-сборка и её выходные файлы.

## 9. Вне рамок

| Требование | Почему не сейчас |
|---|---|
| G01 — полноценный диалог с LLM и автоматическая серверная отправка формы | Выбранный бесплатный Pages-вариант статический; посетитель связывается через Telegram или email-приложение. |
| R04 — собственный домен или платный хостинг | Для публикации достаточно бесплатного адреса `github.io`; пользователь выбрал бесплатный Pages-вариант. |
| R02, R05i — новый дизайн, новые кейсы или переписывание материалов | Запрошено превратить существующий репозиторий в сайт, поэтому сохраняются его содержание и визуальная основа. |

## 10. Обработка сбоев

- Если сборка в Actions завершается ошибкой, новый артефакт не публикуется; причина доступна в журнале workflow.
- Если приложение не настроило почтовый клиент, адрес email и Telegram остаются видны как прямые контакты.
- Пути к `public/`-ресурсам должны учитывать базовый путь репозитория; `basePath` автоматически меняет пути внутренних ссылок Next.js, но его префикс нужно добавлять к публичным файлам в самом коде. Основание: [Next.js basePath](https://nextjs.org/docs/app/api-reference/config/next-config-js/basePath) и [Next.js public folder](https://nextjs.org/docs/app/api-reference/file-conventions/public-folder).
